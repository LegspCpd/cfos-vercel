feat(gatekeeper): GitLab write tool + in-session side-effect approval for external tools

Continues the Gatekeeper work: external write operations now run from inside the
agent chat only after an explicit approve step, and GitLab gets a write tool.

- GitLab write tool: new POST /api/gitlab/tool with list_projects (read) and
  create_issue (write). The write tool refuses unless the connection has write
  access granted (readonly by default) — side-effect approval at the API level,
  mirroring the GitHub create_issue tool.
- New POST /api/gitlab/access toggles write access (readonly/readwrite) and logs
  a gitlab.access_change audit entry. /api/gitlab/status now returns writeAccess.
- In-session approval: new GatekeeperTools panel (bottom of the agent chat) lets
  the user stage a GitHub or GitLab create-issue operation, see exactly what will
  run, and only then Approve to execute. Results echo back into the chat as an
  assistant message. A read-only connection refuses even an approved write.
- api.ts gains githubTool / gitlabTool / gitlabSetAccess; gitlabStatus type extended.
- i18n: gatekeeper.* keys added (zh/en).

Google write tools deferred: the Google OAuth scope currently does not include
write scopes (e.g. gmail.send), so a write tool would 401. Enable write scope in
the Google consent screen first, then the tool can be added.

Verified: tsc --noEmit clean, oxlint 0 errors.
