feat: hide unconfigured OAuth on login/signup + encrypt OAuth tokens at rest

1) Login & signup pages now show only the OAuth providers whose env vars are set,
   matching the Connections page. connectionsAvailable() gained "microsoft"; the
   login and signup pages fetch it and conditionally render each provider button
   (and the "OR" divider) so an unconfigured provider never shows a dead button.

2) SECURITY: OAuth access tokens were stored in plaintext despite schema comments
   claiming "encrypted at rest". Now they are encrypted with AES-256-GCM keyed off
   AUTH_SECRET (encryptSecret) at every write point:
   - github: saveGitHubConnection encrypts; getGitHubToken decrypts.
   - gitlab: callback encrypts accessToken; gitlab/tool decrypts (tolerant of
     legacy plaintext rows).
   - google: callback encrypts both accessToken and refreshToken (the long-lived
     refresh token was the most sensitive plaintext).
   Reading uses decryptSecret ?? raw so existing plaintext rows keep working.

3) signup error handler no longer echoes internal e.message to the client (logs it
   server-side, returns a generic message) to avoid leaking DB/stack details.

Deployment note: encrypted tokens depend on AUTH_SECRET — do not rotate AUTH_SECRET
or existing connections' tokens become undecryptable.

Security scan (code-explorer) also reviewed Gatekeeper code, rate limiting, and
auth. Rate-limit multi-instance/IP bypass (M1) needs distributed limiting (Redis),
deferred; connect-callback login-state double-check (H2) is non-exploitable due to
HMAC state + session-checked connect entry, left unchanged to avoid breaking the
third-party-cookie-less flow.

Verified: tsc --noEmit clean, oxlint 0 errors.
