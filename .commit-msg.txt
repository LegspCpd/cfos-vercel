fix(deploy): random project names (app-xxxx) + reuse existing project per workspace

Deploys previously collapsed onto one "app" project (slugify hard-coded fallback)
which rejected further Direct Uploads (502). Now:

- slugifyProject returns "app-" + a random 10-char hash, so every new project name
  is collision-free and never clashes with another workspace.
- /api/deploy reuses the workspace's most recent deployed project name, so
  redeploying the same workspace doesn't pile up new projects; a fresh workspace
  gets a fresh random name.
- /api/deploy catch logs the full CF error server-side and returns a non-empty
  message to the client.

Also removes a stray temp file.

Verified: tsc --noEmit clean, lint clean.
