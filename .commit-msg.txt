feat: one-click workspace deploy to Cloudflare Pages + short links

Adds a Deploy feature: deploy any workspace to Cloudflare Pages from the
Workspaces page, with auto short links, deployment history, on-demand status
checks, and custom-domain binding.

Backend:
- prisma Deployment model (userId, workspaceId, pagesProject, cfDeploymentId,
  status, pagesUrl, shortUrl, customDomain, error, timestamps).
- src/lib/cf-pages.ts: CF Pages client (ensure project, Direct Upload deploy via
  SHA-256 manifest + missing-hash upload, get deployment status, bind domain).
  Env: PAGES_KEY (API token), PAGES_ACCOUNT_ID.
- src/lib/short-link.ts: sink.cool client (upsert link -> short URL). Env: S_LINK,
  S_LINK_BASE (default https://sink.cool).
- API routes: POST /api/deploy (deploy a workspace), GET /api/deploy/list,
  GET /api/deploy/:id/status (check now), POST /api/deploy/:id/domain (bind).
- audit events: deploy.pages, deploy.bind_domain.

Frontend:
- Workspaces page: "Deploy" button next to "New" opens a right slide-out panel.
- DeployPanel: pick a workspace -> Build & deploy -> shows Pages URL + short link
  (copy), deployment history with check/open, and custom-domain binding.

Docs:
- New cloudflare-deploy.md (zh/en) + nav entry + index links.
- env.md + .env.example document PAGES_KEY / PAGES_ACCOUNT_ID / S_LINK / S_LINK_BASE.

Deployment note: PAGES_KEY needs Cloudflare Pages Edit/Deploy permission; the
account id comes from PAGES_ACCOUNT_ID (not CF_ACCOUNT_ID). Short links require
S_LINK.

Verified: tsc --noEmit clean, oxlint 0 errors.
